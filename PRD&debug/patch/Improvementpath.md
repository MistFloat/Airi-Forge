## 改进前
单纯从 Agent Harness 角度看，现在的 AIRI 已经从“聊天 SDK 外面套功能”升级成了“带持久控制面的 Agent Runtime 原型”，但还没有成为真正完整的 Harness。


| 维度 | 当前评价 | 核心判断 |
|---|---:|---|
| 事件与回放 | 较好 | 已有事件溯源骨架，但日志还不是唯一真源 |
| Turn 控制 | 较好 | 精确中断、owner 隔离、刷新恢复设计正确 |
| Goal/Schedule | 中上 | 状态机可靠，但调度执行仍依赖 renderer |
| 后台任务 | 一般 | 有生命周期记录，没有独立任务执行器 |
| 可恢复工作流 | 偏弱 | 目前只是 `deliver` 检查点，不是工作流引擎 |
| 工具与安全 | 偏弱 | 缺权限、幂等、审批、重试和副作用治理 |
| 长期运行能力 | 偏弱 | JSON 全量写入、全量回放，不适合无限增长 |


## 改进后
- 会话事件日志成为统一事实源。
- Turn、用户消息、助手消息实现主进程原子持久化。
- Prompt 落盘后才请求模型。
- 工具调用实现“先记账、后执行、再结算”，崩溃副作用标记为 `uncertain`。
- 长短期记忆改为事件派生，并支持持久化消费游标与启动重放。
- 刷新恢复保留完整多模态消息。
- Self Prompt、Goal、Schedule、视觉事件、后台任务和工作流能力均保留。
- Eventa IPC 使用类型化、可等待的持久化屏障。

验证结果：

- Core Agent：118/118 测试通过。
- Agent Runtime：16/16 通过。
- Stage UI 相关：14/14 通过。
- MCP：3/3 通过。
- Core 类型检查、定向 ESLint、桌面端生产构建通过。

仓库级检查仍有既有问题：`DeepSeekdsh/.oxlintrc.json` 阻塞全局 lint，另有部分无关类型错误和 Windows symlink 测试失败。现在可以开始桌面端实际测试。
